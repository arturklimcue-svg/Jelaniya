# Вишлист вдвоём 🎁

Общий вишлист подарков для двоих: Telegram-бот + мини-приложение (WebApp).
Один вишлист на двоих — партнёр видит, что вы загадали, и наоборот.

## Возможности

- **Вишлист на двоих** — каждая карточка с фото, ценой, категорией и приоритетом
- **Куплено / Вручено** — владелец отмечает «Я купил(а)» в своём списке; партнёр отмечает «Вручил(а)!», и подарок с фото уходит в историю
- **«Мне тоже»** — скопируйте желание партнёра в свой список
- **Идеи подарков** — копилка + генератор идей для партнёра
- **Сюрприз** — скрыть покупку от получателя до указанной даты
- **Реакции** — ставьте ❤️/🔥 и видите, кто что хочет больше
- **Календарь дат** — дни рождения и праздники; бот пришлёт напоминание и открытку в день события
- **Голосовые пожелания** — запишите, что бы хотели
- **Интересы и хобби** — список увлечений с подсказками «что купить», видно партнёру
- **История подарков** — фото вручений
- **Уведомления в боте** — о новом желании в списке партнёра
- **Добавление по ссылке** — перешлите боту ссылку на вещь, она попадёт в вишлист
- **Тёмная тема**, общий фон, категории, экспорт списка
- **Офлайн** — PWA/Service Worker, работа из кэша

## Запуск

```bash
pip install -r requirements.txt
export BOT_TOKEN="токен от @BotFather"
export WEBAPP_URL="https://ваш-домен/"
python main.py
```

- `BOT_TOKEN` — токен бота
- `WEBAPP_URL` — публичный URL мини-приложения (кнопка меню бота). Если не задан,
  берётся из `SITE_URL`, затем `DOMAIN`, затем `PAGES_FALLBACK` (GitHub Pages)
- `PORT` — порт веб-сервера (по умолчанию 8080)
- `GITHUB_USER` — ваш ник для диагностики (необязательно)

Данные хранятся в `data.json`, загруженные фото — в `uploads/`.

## Деплой на Bothost

1. Создайте бота на [bothost.ru](https://bothost.ru):
   - **Платформа**: Telegram
   - **Библиотека**: Python
   - **Bot Token**: токен от @BotFather
   - **Git URL**: `https://github.com/arturklimcue-svg/Jelaniya`
   - **Ветка**: `main`
   - **Главный файл**: `main.py`
2. **Дополнительные настройки** → включите галочку
   **«Использовать собственный Dockerfile»** — обязательно, иначе порт будет
   занят платформенной обёрткой и будет работать только бот (без сайта/API).
3. Включите **домен** и укажите **порт 8080**.
4. **Зарегистрируйте домен мини-приложения у @BotFather**: команда
   `/setdomain` → выберите бота → введите домен (например,
   `bot-....bothost.tech`). Без этого Telegram не пришлёт в приложение
   `initData`, и вход через бота работать не будет.
   ⚠️ Домен должен быть **стабильным**: не пересоздавайте бота на Bothost
   при каждом обновлении — перезапускайте существующего, иначе домен
   изменится и его нужно будет регистрировать заново.
5. «Создать» / «Развернуть». После этого напишите боту `/start`.

`main.py` умеет работать и без Dockerfile: если порт уже занят обёрткой
платформы, он пропускает веб-сервер и запускает только бота.

## GitHub Pages (статическая копия)

`.github/workflows/pages.yml` публикует папку `public/` на GitHub Pages.
Это удобно как статический превью и как фолбэк для кнопки бота
(`PAGES_FALLBACK`). Полный функционал (API, авторизация, загрузки) доступен
только на сервере (Bothost/Docker или локально).

## Как это работает

1. Два человека открывают бота — они становятся парой (первый — «solo», второй привязывается к нему).
2. Каждый загадывает подарки в мини-приложении; если владелец купил желание сам себе, он отмечает «Я купил(а)». Партнёр выбирает подарки в «Планы», а при вручении нажимает «Вручил(а)!».
3. Вручённые подарки с фото попадают в общую историю.

## API

Все эндпоинты принимают `initData` (Telegram WebApp) в query-параметре.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/data` | весь общий список (вишлист, идеи, история, события, категории, фоны) |
| POST | `/api/items` | добавить подарок/идею (`kind: wishlist|ideas`) |
| PATCH | `/api/items/{id}`, `/api/ideas/{id}`, `/api/history/{id}` | изменить поля |
| POST | `/api/items/{id}/delete` | удалить |
| POST | `/api/items/{id}/copy` | «мне тоже» |
| POST | `/api/items/{id}/gift` | отметить вручение (переносит в историю) |
| POST | `/api/items/{id}/restore` | восстановить удалённое (отмена) |
| POST | `/api/ideas/{id}/to-item` | перенести идею в вишлист |
| POST | `/api/categories`, `/api/categories/{name}/delete` | категории |
| POST | `/api/upload` | загрузка фото/аудио (лимиты, проверка магии, webp) |
| POST | `/api/background` · `/set` · `/{index}/delete` | общий фон |
| GET | `/api/diag` | диагностика авторизации |
